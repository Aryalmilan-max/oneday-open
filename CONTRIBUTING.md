# Contributing

Thanks for helping make everyday tools clearer and more reliable.

1. Open an issue describing the user task and how to reproduce the problem.
2. Keep changes focused. A new tool needs a clear name, input, output, limitation note, and keyboard-accessible controls.
3. Run `npm run check` and test the affected tool in a mobile-sized browser.
4. Include a small before/after example in the pull request. Never include real private documents or credentials in fixtures.

We especially welcome translations, accessibility fixes, performance improvements, browser compatibility reports, and realistic example workflows. Do not add tracking, hidden uploads, or unsafe auto-execution of user-supplied text.
